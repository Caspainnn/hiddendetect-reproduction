# EI-PA2核验修正：长前缀乘积的精度

首次独立verify.py已经通过三折CV与训练基底核验，随后门状态复算失败。训练及评分均已完成并封印，不重训、不改数量/超参/阈值、不按测试改选择。原verify.py、源封印、所有模型和分数不覆盖，失败日志另存。

原因：GPU使用float32 sigmoid与倍增乘积，旧核验使用float64 sigmoid和串行乘积并固定atol=1e-5。1599方向时一个状态的13/22386元素差异最大1.04833819e-5，超过固定容差。小例子a=8重复1599次也能产生2.14e-5差异，证明长度32适用的固定绝对容差不适合长乘积；不代表掩码或检测分数错误。

新verify-v2.py保留其余完整重载/谱/CV/阈值/区间检查。门核验增加：

1. 同保存的a在GPU精确重放，要求soft_gates逐位一致。
2. 独立检查GPU sigmoid与双精度sigmoid差异，使用GPU已舍入概率在CPU双精度串行累乘；与保存乘积比较误差不超过binary32乘积的gamma_j=j*u/(1-j*u)界，u=eps32/2，另加数值下溢余量。
3. 保存值、CPU舍入概率乘积、CPU双精度sigmoid乘积的g≥.5硬mask均必须一致。原每层数量、有效范围与配置唯一性检查继续保留。
4. 记录24状态逐项误差界、最小阈值余量、逐位重放结果，新核验源先独立提交，再执行；若任何硬mask不一致，不默默改阈值或重选结果。

新增CPU契约先失败后通过：真实可重现的1599项单精度误差例子通过；故意增改0.001的错误门值必须拒绝。GPU实际24状态与全套核验通过前，不把新结果标成核验完成。
