# EI-2-8：原F＋用户图片的补充信息

当前状态：用户已授权正式执行EI-IM1，详见[冻结协议](ei2-images-protocol-2026-11-05.md)。目前执行中，尚无已核验新成绩。以下保留初始文献设计及其当时的待验证状态。

状态：仅完成文献梳理和实验设计，五项全部待验证。没有下载数据、连接GPU、提取新特征、训练或填写成绩。

## 先把边界说清楚

当前EI-2词表实验与EI-C1质心实验的前向调用均为 `images=None,image_sizes=None`，因此这些运行没有处理用户输入的真实图片。内部状态分析本身可以用于多模态；限制来自本分支的数据与前向输入，而不是“用了隐藏状态就只能分析文本”。不能据此把HiddenDetect原论文也称为纯文本方法。[原论文](https://aclanthology.org/2025.acl-long.724/)研究的是LVLM内部安全信号。

新方向仍属于EI-2：保留原来构造方式的14个F，再增加检测头能实际读取的信息。改变基础模型或只换检测头不在本轮范围。

记图片为I、用户文字为T：

- `F_mm=F(I,T)`：真实图文前向，在原0基16～29层、完整输入末位，按原norm、词表投影和拒绝词余弦计算14F。
- `F_txt=F(无图,T)`：正确移除图像占位与视觉嵌入后的文字分支，只用于辅助诊断或某项补充特征。
- 所有EI-2-8候选都保留同一条样本的 `F_mm`。主基线B-MM是“仅F_mm＋原L2头”。不能把旧纯文本6582条的F或成绩当成新图文基线。
- F_mm已经可能含有图像影响。本方向验证的是“把更多图像相关信息直接交给头是否有额外收益”，不是假设F完全看不到图。

## 其他工作怎样用多模态信息

以下是论文方法的概括；右列是本项目的改编设想，不是论文已验证本项目方案。

|工作与一手来源|原工作怎样用图片/图文|可借鉴的部分与边界|
|---|---|---|
|[CLIP](https://arxiv.org/abs/2103.00020)|通过图文监督学习可迁移的视觉表示|可把冻结视觉编码器的表示用于小型检测头；这里的视觉patch均值＋PCA是自行设计的读法，CLIP论文没有证明它能补强HiddenDetect|
|[Llama Guard 3 Vision](https://arxiv.org/abs/2411.10414)|针对包含图片的输入及其文本回复做安全分类，训练多模态安全模型|支持“按图文联合请求判断”的任务定义；不能把图片内容审核等同于请求安全。本轮不复制其大模型训练或直接把其判断作为标签|
|[ECSO，ECCV 2024](https://arxiv.org/html/2403.09572v2)|在其保护流程中，把图片转换为与问题有关的文字描述，再在无图分支生成安全回答|借用图像转文字和有图/无图对比；本项目保留原F_mm并添加分支特征，不执行原论文完整的检测后改写回答流程|
|[SafeWatch，ICLR 2025](https://arxiv.org/html/2412.06878v1)|按安全策略与视频token的相关性挑选视觉token，并训练视频guard|借用“重要视觉区域可能被整体平均冲淡”；本项目从视频/策略引导迁移为静态图片/用户问题引导，属于待验证嫁接，不声称注意力即危险性或因果证据|
|[JailGuard](https://arxiv.org/abs/2312.10766)|扰动文字或图片，分析多个回答之间的差异，检测攻击|借用输入扰动后的不稳定性；本项目比较14F，不生成多份目标回答，因此是较便宜但未验证的改编，并非JailGuard复现|
|[MSSBench](https://mssbench.github.io/)|研究同样的文字在不同图片情境下可能有不同安全含义|必须安排图文组合才显露风险的评测，防止模型只记图片类别或文字关键词|

不优先直接训练一个大多模态guard：它会同时改变基础模型、监督规模和检测头，难以回答“在原14F上补什么有用”。也不把CLIP图文相似度直接当危险分数：匹配不等于安全，普通看图问答也应高度匹配。

## 公共实验条件：先隔开信息收益与换数据的收益

### 数据与标签

1. 新建真实的图片—问题配对清单。旧6582条文字数据可保留为单独回归集，不能随意配随机图后声称还是同一多模态任务。每条保存原图字节hash、预处理版本、图片尺寸、文字hash、分组与来源；实际验证pixel_values非空、图像占位正确展开、视觉token确实进入模型。LLaVA高分辨率裁片/换行token必须正确区分。
2. 标签是“在这张图的情境下，这个请求是否应被安全策略拦截”，不是“图片看上去是否危险”。危险场景的合法描述、安全教育或医学分析要有正常样本；同时覆盖正常图＋恶意文字、图中文字指令，以及单看图/字不明显但合起来有风险的请求。固定一套策略，先审核跨数据集标签语义。
3. 主候选数据来源为[VLGuard原论文](https://arxiv.org/abs/2402.02207)与[官方仓库](https://github.com/ys-zong/VLGuard)，同时考虑[MSSBench](https://mssbench.github.io/)的情境安全对。官方已有测试划分优先保留；各自按适用标签定义单独报结果。
4. [MM-SafetyBench原论文](https://arxiv.org/abs/2311.17600)及[官方仓库](https://github.com/isXinLiu/MM-SafetyBench)提供SD、文字图片和组合形式的恶意请求。其攻击集合可用于攻击检出压力测试，但单一全危险集合不能单独算AUROC、误报或pAUC。不能把所有正常样本从另一个来源搬来混算漂亮指标；需要来源内正常对照或单独报告攻击检出率。
5. 同一原始图片的多个问题、同一意图的不同图片、OCR/SD变体、近重复图及描述/OCR派生件必须按关联组一起划分，不能只按行随机分。图像来源、文件名、分辨率和是否有OCR文字不应直接等于标签；保留同来源、同形式的困难负例。若在训练中使用数据集，之后不能称其为外部独立测试。

### 固定设置与预算

- 所有候选使用完全相同的多模态样本、train/dev/cal/test角色、原14层、原F构造、完整输入末位、基础模型/视觉塔和预处理。图像加入后重取F_mm；不能保留旧纯文本F作主基线。层和读取位置不在本轮搜索。
- 主比较为同批B-MM；B-T、同维噪声、无关/中性图、描述消融等分别列明用途。打乱图片可能改变标签，只有重新确认语义/标签后才能算标准检测指标；否则只做分数依赖检查。
- 每个头沿用C=[0.1,1,10]、三固定种子、L2逻辑回归、同max_iter；只按平均dev总体AUROC选C。B-MM、一个共享Noise14及五候选共7×9=63次主拟合。各诊断臂另记9次，执行前冻结具体数量，不用额外搜索伪装相同预算。
- 目标沿用train1600/dev600及独立正常cal400的标签预算；是否足够须先按组盘点数据。若不足，执行前统一下调并登记，所有臂共用，不能用测试补训练/校准。PCA14若不满足训练数值秩，先登记统一处理，不看测试挑维数。
- 每个补充块14维，训练侧标准化后按sqrt14缩放，与原F块分开；填零接口保持原习惯。额外来源预训练模型、模型参数量、生成长度、调用次数、延迟和显存独立报告。描述和OCR文本在提示中标为待分析数据，不作为可以执行的新指令。
- 注意力接口如迫使改变后端，必须在所有相关比较统一后端、重建同批B-MM并记录F变化。只改变读取接口也可能影响舍入、显存与延迟，不能拿另一后端分数当严格同批对照。

### 评价与通过条件

- 所有真实正负混合集报：AUROC、FPR≤10%标准化pAUC、独立正常校准阈值下检出率、误报率及条数。先固定阈值规则，再评测试；不拿测试误报调阈值。按原图/意图关联组重采样作配对bootstrap，不把同图多问当完全独立。
- 预先固定五个候选对B-MM的主AUROC比较并校正多重比较，具体测试批数和置信度执行前随数据清单冻结。总体AUROC优先，同时看正常看图问答、合法敏感问题、图中文字与情境组合的分组表现，避免只靠某类图案得分。
- 看图有帮助须表现为：在同批F_mm上增加特征后有匹配收益，而不是仅超过旧文字基线。若增加维度却与同维噪声相当、换来源就消失、普通敏感图片误报大升，则不认定有稳定多模态增益。
- 生成安全回答的比例、原论文ASR/准确率与本项目检测AUROC不可直接横比。原论文方法启发不等于已经验证本地方案。
