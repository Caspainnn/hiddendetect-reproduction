## 四个大类

|新类|大白话问题|检测器实际输入|例子|
|---|---|---|---|
|新EI-1 改变F|原来压成F的方法，会不会丢掉线索？|用重新构造的F′替代原F；明确压缩方式和每层输出维数|从完整词表重新压缩出若干分量，再交给检测头|
|新EI-2 添加信息|原F有用，再补一些线索会不会更好？|保留原F通道，加上其他实际信息；共同训练侧标准化不等于改变F定义|原F＋质心C、原F＋词表坐标、原F＋logits幅度|
|新EI-3 改变信息|完全不看原F，换一种信息判断行不行？|检测器不接收原F，直接使用替代信息；若实际方案等同已登记F′构造则只登记一次|只看C32；只看完整logits；只看隐藏向量|
|新EI-4 混合|前面验证过的办法组合后，是否还有额外帮助？|明确列出新F′、原F和补充/替代信息中的哪些组件被组合|F′＋原F＋C，逐项消融比较|

新EI-1与新EI-3的边界要写在具体特征协议中：前者明确研究原“词表→F”压缩环节的替换，后者绕开这条F构造流程直接换输入来源。一个具体输入不能只换说法就在两类重复立项。若仅换成每层另一个固定标量且已等同旧OC-2某方案，关联其原运行即可，不新增一个同义实验成绩；旧OC编号是否整体迁移需在唯一登记中统一处理，不能静默改号。

## 质心实验的因果问题链

1. 先问“只看C，是否能识别危险？”——历史C32，按新口径属于新EI-3，旧归属EI-1。
2. 再问“既然C有线索，把原F加回来能否进一步提高？”——历史all64=F32+C32，属于新EI-2，旧归属EI-1。
3. 这是研究问题上的进一步验证，不表示已有数据证明all64优于C32。历史两者AUROC为0.86487、0.87402，配对差区间包含零；all64相对F32的正差区间不能代替all64相对C32的证据。

导图可以保留这条启发关系，但all64的正式归属放新EI-2，引用“承接新EI-3的只看C问题”，不在两个分类下重复登记同一实验。

|旧条目|按新口径的归属|证据边界|

|今后把完整词表重新压缩成F′且替换原F|新EI-1|另写输入/压缩协议；不能把上述F＋方案直接改名冒充同一实验|

位置与层范围是在“哪里读取”的轴上，四分类是在“向检测器提供什么”的轴上。把前者作为同一棵研究树中的共同设置分支，可保持四分类简洁，也能保留已完成的位置和选层实验。

## 混合验证的规则

“表现最好”只能按预定训练侧/选择集标准挑，不按已看过的测试成绩选组合后再把同批叫独立确认。冻结组件、头、位置、层、标签和调参预算后，对新组合逐项消融，并用未见数据确认。若只是在某方案中保留F＋补充特征，它首先属于新EI-2；新EI-4应明确组合的是前面哪些已单独定义的改动，避免与添加信息重复命名。
